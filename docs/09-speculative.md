# 09 · 待验证构想

> 本文件收录尚未验证的设计构想。**这些不是承诺，是候选方向。** 每条标注了脑对应物、计算机优势、具体设计、项目价值与可行性。

---

## 零、根本不对称（一切构想的出发点）

| | 人脑 | 计算机 |
|--|------|--------|
| 单元速度 | 慢（神经元约 1kHz） | 快（GHz） |
| 并行度 | 极大（860 亿神经元） | 有限（GPU 几千核心） |
| 寻址 | 无地址，只能联想 | 精确随机访问 |
| 状态复制 | 不可能 | 微秒级快照 |
| 权重更新 | 极慢（小时级） | 毫秒级 |
| 能耗 | 20W | 300W |

**两个互补方向：**

```
方向一：设计补速度（硬件受限，用架构绕开）
   稀疏门控 · 压缩记忆 · 双通路 · 条件计算
   -> 这部分已经在做（见 02 / 03）

方向二：速度补设计（架构受限，用算力突破）
   并行推演 · 精确检索 · 实时权重更新 · 状态快照
   -> 这部分是本文重点
```

**最有价值的创新在方向二。** 方向一是在追赶人脑，方向二是在做超越人脑的事。

## 构想 1：并行假设推演（分叉思考）★最看好

**脑对应物：** 人做决定时会在脑中模拟几种可能（"我这么说她会怎么反应"），但一次只能模拟一两种，而且很慢。

**计算机优势：** GPU 可以同时算 100 种可能。

**设计：**

```
输入: "她突然沉默了"
    |
    +- 分支 1: 她在生气 -> 继续写 20 token
    +- 分支 2: 她在难过 -> 继续写 20 token
    +- 分支 3: 她在害羞 -> 继续写 20 token
    +- ... x 8 条分支并行
    |
    v
一致性评分器（内部，几毫秒）
    |
    v
选出最符合当前情境的那条 -> 提升为主通路
其余剪枝
```

**项目价值：** 模型内部探索"剧情可以往哪走"，选最自然的。人类作者要反复推敲几分钟，模型在一次前向传播里做完。**这是计算机独有的能力——人脑无法同时维持 8 条清晰的故事线。**

**可行性：** 中。需要额外训练评分器；算力开销约 3-8 倍（可通过只对关键 token 推演来降低）。

## 构想 2：记忆的精度分级

**脑对应物：** 人无法选择"这条记忆要精确存还是模糊存"。重要的事可能记错，琐事可能记得很清楚——**不可控**。

**计算机优势：** 可以显式选择存储精度。

**设计：**

| 级别 | 存储形式 | 用途 | 成本 |
|:---:|----------|------|:---:|
| L0 | 精确 KV（无损） | "她原话说了什么" | 高 |
| L1 | 高保真嵌入 | 重要情节、承诺 | 中 |
| L2 | 压缩摘要（gist） | 一般对话 | 低 |
| L3 | 只有句柄（可回溯） | 背景信息 | 极低 |

模型自己决定：换衣服这种状态变化 -> L1；一句"嗯" -> 丢弃。

**项目价值：** 比人脑强——人脑记忆精度不可控，计算机可以按重要性精确分配存储预算。

**可行性：** 高。实现成本低，直接解决"该记什么"的核心问题。

## 构想 3：多时间尺度并行

**脑对应物：** 脑用不同频率的振荡同时处理不同时间尺度（gamma 管细节，theta 管记忆，alpha 管门控）。这是脑真实存在的机制。

**计算机优势：** 脑的振荡是**串行复用**同一批神经元（所以慢），计算机可以让不同时间尺度真正并行在不同张量上。

**设计：**

```
输入
 +- 快通路（token 级）    -> 保持语言流畅
 +- 中通路（段落级）      -> 保持逻辑连贯
 +- 慢通路（整段对话级）  -> 保持叙事弧线、人设一致
 +- 超慢通路（跨会话级）  -> 长期人格、关系演进
      ^ 全部并行，通过交叉注意力同步
```

**项目价值：** 快通路管"这句话说得顺不顺"，慢通路管"这个人设崩没崩"。不同尺度的问题分开并行处理，比混在一起更清晰、更快。

**可行性：** 中。是双通路架构的自然扩展（N 通路），但参数量和显存会上升。

## 构想 4：毫秒级实时权重更新

**脑对应物：** 人学习需要反复强化，形成长期记忆要几小时到几天（睡眠巩固）。

**计算机优势：** 一次梯度下降只要几毫秒。

**设计：**

```
对话中遇到新信息
    |
立即做一次小梯度更新（只更新记忆模块，不动主模型）
    |
几毫秒后，模型"学会"了这个新事实
    |
后续对话立即受益
```

**项目价值：** 这是 Titans 的核心思想（测试时训练）。人脑需要睡一觉才能巩固，计算机当场就学会。

**注意：** 更新的是**记忆模块**，不是主模型。主模型冻结（保证稳定性），记忆模块快速适应。

**可行性：** 中-低。需要保证训练稳定性，且推理时做梯度更新会拖慢速度（需要异步 / 低频率触发）。

---

## 构想 5：状态快照与反事实回溯

**脑对应物：** 你**无法**回到十分钟前的心理状态重新想一遍。人脑不能回滚。

**计算机优势：** 状态快照只要几微秒。

**设计：**

```
对话进行中 -> 自动保存状态快照
    |
"刚才那句话效果不好" -> 回滚到快照 -> 换个说法
    |
或者：同时维持两条对话线，用户切换
```

**项目价值：** 用户可以"重来"某段剧情，模型精确恢复到那个时刻的状态（包括所有记忆）。**人脑完全做不到。**

**可行性：** 高（实现简单）。需要存储管理策略。

---

## 构想 6：穷举式记忆检索

**脑对应物：** 人回忆靠联想，**无法穷举**。想不起某件事就是想不起。

**计算机优势：** 可以精确扫描全部记忆，几毫秒内找到。

**设计：**

```
记忆库（100 万条记忆令牌）
    |
当前语境 -> 生成 query
    |
精确最近邻搜索（全库，非近似）
    |
返回 Top-K 最相关记忆
```

**项目价值：** 超越人脑——人只能"想起来"或"想不起来"，计算机可以保证找到**所有**相关记忆。

**可行性：** 高。工程上就是向量检索，只是要保证在模型内部完成。

---

## 构想 7：并发自我（多上下文并行）

**脑对应物：** 脑有多个网络同时运行（默认模式网络 DMN、显著性网络、执行控制网络）。

**计算机优势：** 可以维持更多并行上下文。

**设计：**

```
并发上下文 A: 对话
并发上下文 B: 环境监控（视觉 / 传感器）
并发上下文 C: 长期规划
      ^ 共享记忆层，互相可见
```

**项目价值：** 对机器人 / 具身智能尤其有用——一边聊天、一边看路、一边想着待办事项。

**可行性：** 中。是双通路的进一步扩展。

---

## 构想 8：空闲时精确回放学习

**脑对应物：** 人做梦时会重放白天的经历，但**不精确**（梦会扭曲）。

**计算机优势：** 可以精确重放，并且可控。

**设计：**

```
空闲时（类比睡眠）
    |
重放过去的对话（精确，不扭曲）
    |
找出"当时回答不好的地方"
    |
生成改进样本 -> 微调记忆模块 / 收集训练数据
```

**项目价值：** 模型可以自我改进，且不像梦那样失真。

**可行性：** 中。依赖巩固机制（见 03）。

### 构想 9：O(1) 常驻记忆架构（参考 DeepSeek V4 的 "Engram"）★ 待调研

## 优先级建议

| 优先 | 构想 | 理由 |
|:---:|------|------|
| 1 | **并行假设推演** | 计算机独有，对 RP 质量提升最直接，天然利用 GPU 并行 |
| 2 | **多时间尺度并行** | 脑真实机制 + 计算机可真正并行 = 双重优势 |
| 3 | **记忆精度分级** | 实现成本低，直接解决"该记什么" |
| 4 | 穷举式记忆检索 | 工程上容易，收益明确 |
| 5 | 状态快照与回溯 | 实现简单，体验独特 |
| 6 | 实时权重更新 | 前沿但难度高 |
| 7 | 并发自我 | 面向机器人，非当前优先 |
| 8 | 空闲回放学习 | 依赖巩固机制成熟 |
| 9 | O(1) 常驻记忆（Engram） | **待调研**，若成立会改变记忆系统设计 |

## 总原则

```
设计补速度（硬件受限，用架构绕开）:
   稀疏门控 · 压缩记忆 · 双通路 · 条件计算

速度补设计（架构受限，用算力突破）:
   并行推演 · 精确检索 · 实时权重更新 · 状态快照
```

**只做第一条线，是一个"不错的小模型"。
加上第二条线，它会是"一种新的智能形态"——用计算机的方式思考，而不是模仿人脑。**
