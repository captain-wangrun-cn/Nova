## 里程碑 1：核心骨架（最关键）

   - 预测编码门控
2. 🟡 **记忆模块** —— **L0 精确 KV 已落地（S4，[reports/s4-memory-min.md](../reports/s4-memory-min.md)，D31）**；"压缩"与"记忆令牌"未做
   - ⏳ 记忆令牌生成（`[128, 2560]` + `[128, 512]` 独立键）—— **要训练**，属里程碑 2
   - ✅ 键值联想检索 —— 用模型**自己的** `Q·K`（按注入后真实位置旋转 + softmax 质量），**零新增参数、零训练**；实测 6 条候选 × 8 问 **8/8**
   - ⏳ 压缩 —— 现在是无损 KV，体积 **240 KiB/token**，随区间线性增长
3. ✅ **记忆持久化**
   - safetensors 读写
   - 加载 / 保存 / 校验
   - 另加：`schema_digest` + `model_fingerprint` 不匹配**拒绝加载**（D09）
4. ✅ **单元测试**（`pytest tests -q` → **93 passed**；第六轮 ① 新增 `test_kvattn.py` 21 条）
   - ✅ 前向传播正确性
   - ✅ 显存占用达标（< 7GB）—— 双通路 + 记忆 + 1024 槽位 cache 峰值 **5.17 GiB**
   - ✅ 交叉注意力隔离性
   - ✅ **记忆跨轮保持**（最关键）—— 第 1 轮写入 → **20 轮后 8/8 取回**；不注入 0/8；**存盘重启（跨进程）仍可取回**

**验证标准：**
- ✅ 在 4060 上跑通一次完整前向传播
- ✅ **记忆能在多轮之间保持信息**（S4：8/8）—— 落地形式是 **L0 精确 KV**，不是"记忆令牌"；后者要训练，顺延到里程碑 2
- ✅ 显存不超 7GB（5.17 GiB）

**风险：** 显存超限、交叉注意力实现错误

## 里程碑 2：质量与长上下文

**目标：** 让对话质量可用，长上下文可用

**任务：**
1. 数据合成
   - 状态跟踪样本（最关键）
   - 对话质量样本
   - 工具调用样本
2. 训练

   > **语言顺序（硬约束）：先纯英文，后中文。** 详见 [15-language-plan.md](15-language-plan.md)、D02 / D03 / D18。

   - 阶段 A：只训交叉注意力 + 门控（几小时，数据用纯英文）
   - 阶段 B1：Chat 通路 LoRA，**纯英文**对话 / RP 数据 → 建立"怎么做对话"的地基
   - 阶段 B2：**中文 LoRA**，叠加在 B1 之上（**必含中英混杂样本**），数据量约为 B1 的 30-50%
   - 阶段 C：Agent 通路 LoRA（工具 / 推理数据，英文）
   - 阶段 D：端到端联合微调（少量混合数据）
   - **过门条件：** B1 通过全部英文验证标准后，才允许进入 B2。**不做中英同时训练。**
3. 长上下文测试
   - 状态跟踪准确率（换衣服能否记住）
   - 多轮一致性
4. 部署优化
   - 量化、投机解码、torch.compile

**验证标准：**
- 换衣服等状态变化能在 20 轮后被正确引用
- 对话质量主观评分达到预期
- 速度达到 60+ tok/s
- 跨语言回归：中文 LoRA 上线后，英文 RP 表现不下降
- 英文阶段数据通过语言过滤（不含中文，见 15-language-plan.md 风险 L4）

## 语言训练顺序（明确约束）

```
里程碑 2
    |
    +-- 阶段 A / B1 / C：纯英文数据 ------------------+
    |                                                  |
    +-- 阶段 B2：中文 LoRA（叠加在 B1 之上）<----------+
    |            必含中英混杂样本
    |
    +-- 阶段 3（里程碑 4）：其他语言 LoRA（可选）
```

**理由摘要（完整版见 [15-language-plan.md](15-language-plan.md)）：**

| # | 理由 | 说明 |
|:-:|------|------|
| 1 | 模式只教一遍 | 状态跟踪 / 角色一致性等行为模式与语言无关，英文学会后中文只需学"怎么表达" |
| 2 | 省 LoRA 容量 | 中英同训会让容量被"中文怎么说"吃掉，两边都学不好 |
| 3 | 数据生态 | 英文 RP / 对话数据在数量和质量上明显更好 |
| 4 | 可升级 | 每种语言独立适配器，可单独重训 / 回滚，互不干扰 |

**注意：** "英文 token 效率更高、更省显存"这条论据对 Qwen 系 tokenizer 需要打折，**待实测**（见 15-language-plan.md 第 2.5 节）。即使该论据不成立，上面 4 条理由仍足以支撑结论。
