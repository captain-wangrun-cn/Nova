# 05 · 速度优化

> 目标：在 RTX 4060 Laptop 8GB 上，把 4B 双通路跑到流畅（目标 100+ tok/s）。

---

## 一、先诊断瓶颈

4060 Laptop 关键参数：

```
显存带宽  ~= 256 GB/s
模型大小  ~= 2.5 GB (4B Q4)
----------------------------
理论上限  = 256 / 2.5 ~= 102 tok/s
实际      ~= 40-60 tok/s
```

**为什么？** 生成每个 token 都要把整个模型的权重从显存读一遍。GPU 算力再强也没用——**它在等数据**。这叫 **memory-bandwidth-bound（带宽受限）**。

**推论：所有能"减少数据搬运"或"一次搬运生成多个 token"的技术，都直接提升速度。**

## 二、四类优化

### 第一类：架构级（免费，不需额外训练）

| 技术 | 原理 | 收益 |
|------|------|:---:|
| **预测编码门控** | 闲聊时 Agent 通路关闭 | +20-30% |
| 共享嵌入 / 输出层 | 两通路共用，少读权重 | +5-10% |
| 滑窗注意力 | KV Cache 变小 | 长上下文下显著 |

**已设计进架构。闲聊时只跑一条通路——这是最大的免费提速。**

### 第二类：训练级（需要训练时实现）

| 技术 | 原理 | 收益 |
|------|------|:---:|
| **MTP 多头预测** | 一次前向预测多个未来 token（DeepSeek-V3 用的） | +80% |
| MLA 式 KV 压缩 | KV 压成潜在向量，Cache 缩小约 90% | 长上下文下巨大 |
| 投机解码友好训练 | 训练时对齐草稿模型 | +100-200% |

### 第三类：推理级（不改模型，部署时加）

| 技术 | 收益 | 说明 |
|------|:---:|------|
| KV Cache 量化（Q8/Q4） | +10-20% | 减少带宽占用 |
| **投机解码** | +100-200% | 小模型草稿 + 大模型验证 |
| torch.compile + CUDA Graphs | +20-30% | 减少 kernel 启动开销 |
| FlashAttention | +10-20% | 融合注意力算子 |

**投机解码是性价比最高的**：用一个 0.5B 小模型快速猜 5 个 token，4B 模型一次前向验证。RP 这种可预测性高的文本，命中率很高。

### 第四类：CPU + GPU 分工

见 [04-async-tools.md](04-async-tools.md) 第五节。要点：

- **不要做层卸载**（CPU 太慢，是负优化）
- 让 CPU 做 GPU 做不了的事：工具执行、IO 预取、KV 换入换出、记忆整理

## 三、DeepSeek 式缓存层级

见 [06-deployment.md](06-deployment.md)。要点：

```
L1: GPU 显存    ~7 GB     活跃 KV Cache     纳秒级
L2: CPU 内存    ~32 GB    热 KV Cache       微秒级
L3: SSD         ~1 TB     冷 KV + 记忆文件   毫秒级
```

## 四、综合速度预估

| 阶段 | 预估 TPS | 说明 |
|------|:---:|------|
| 裸模型 4B Q4 | 40-60 | 基线 |
| + 推理优化 | 60-90 | compile + KV 量化 + FlashAttn |
| + 投机解码 | **100-150** | 性价比最高 |
| + MTP | **130-180** | 需训练时实现 |
| + 预测门控（闲聊时） | **150-200** | Agent 通路关闭 |

**注意：收益不能简单叠加**（有重叠）。保守估计 **2-3 倍提升是现实的**：从 50 到 120-150 tok/s。

参照：人类阅读速度约 5-10 tok/s，所以 120 tok/s 对 RP 是完全流畅的。

## 五、TTFT（首字延迟）优化

| 手段 | 效果 |
|------|------|
| 前缀缓存（系统提示词不重算） | 显著降低 |
| Chunked prefill（长上下文分块） | 降低 |
| 双通路并行预填充 | 略降 |

## 六、量化的权衡（速度 vs 质量）

```
Q4_K_M  ->  2.5 GB,  50 tok/s,  质量 95%
Q3_K_M  ->  2.0 GB,  65 tok/s,  质量 88%
Q2_K    ->  1.5 GB,  85 tok/s,  质量 75%   <- 开始明显掉
```

**建议 Q4_K_M 起步。** 4060 跑 4B Q4 本来就绰绰有余，没必要牺牲质量换速度。

## 七、优化清单汇总

```
[已设计] 架构层
   · 预测编码门控 -> 闲聊时单通路
   · 共享嵌入 / 输出层
   · 异步 Tool（CPU/GPU 天然分工）

[训练时] 训练层
   · MTP 多头预测
   · 记忆令牌（替代庞大 KV）

[部署时] 推理层
   · 投机解码（0.5B 草稿模型）
   · KV Cache 量化
   · torch.compile + CUDA Graphs
   · FlashAttention

[部署时] 缓存层
   · L1 GPU / L2 CPU RAM / L3 SSD
   · 前缀缓存 + 记忆令牌持久化
```
