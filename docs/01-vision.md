# 01 · 愿景与需求

> 本文记录项目的目标、需求，以及需求逐步澄清的完整演进史。**不要删减演进过程**，它记录了"为什么是现在这个设计"。

---

## 一、原始需求（项目起点）

用户最初提出四条：

1. 配置要求低，可以 CPU、GPU、或 CPU+GPU 协同
2. TPS 快，TTFT 快
3. 主要是对话，轻量 agent
4. 主打多模态，长上下文时的准确性和注意力

## 二、需求演进史

### 演进 1：多模态 → 重新定义

用户选中 `TokenRhythm/NeoHorse-1-9B`（9B，Qwen3.5-9B 派生，Apache-2.0，262K 原生上下文，可扩至 1M）。

**关键发现：该模型是纯文本。** 模型卡明确写着 "Vision weights are not included"，接口为 text-in / text-out。

用户随后澄清：重心是 **"对话 + 长上下文的记忆与注意力"**，而不是让模型本身具备视觉理解。

> **已确认（2026-09-21）：多模态需求保留。** 因此基座必须是多模态模型（Qwen3-4B 为纯文本，需更换）。详见 [13-decisions.md](13-decisions.md) 的 D14 / D16。

### 演进 2：对话为主、agent 可有可无 → 双通路并行

- 起点：agent 可有可无，重点是对话
- 用户提出：做成两个模型（一个对话、一个 agent），专攻，像大脑不同区域，互相交换信息、协作、同时进行
- 用户进一步澄清：**不是外部系统程序**（不是 AutoGen 那类多 agent 框架）
- 最终明确：**模型内部的双通路架构**，数据在隐藏状态（tensor）层面交换

### 演进 3：极低配置 → 具体硬件

- 至少要在 RTX 4060 Laptop 上，跑出 4B 级模型的速度
- 曾希望支持手机（如 Gemma 那样）
- 后来明确：**手机先不考虑**，优先桌面
- 质量目标：接近 32B，甚至更好的闭源模型

### 演进 4：长上下文 → 状态跟踪（核心诉求）

- 需求：200-500K 上下文
- 场景：酒馆 RP（SillyTavern）+ 文字工作
- 核心诉求原话：
  > "记住角色，以及自然的故事发展，某些重要因素（例如服装等）不会遗漏，比如前面换了一个服装后面就需要自然而然地记住并融入对话，总而言之就是和人一样。"
- 关键澄清：是 **"像人一样"**，不是完美记忆

### 演进 5：全部在模型内部

用户多次强调，这是硬约束：

- "都是模型自身的，而不是外部系统，代码，agent"
- 记忆必须是模型自身的机制
- 磁盘持久化也要以 **"模型的方式"** 存储（张量），**不是 JSON 或其他数据格式**

### 演进 6：单用户、单人格

用户提出：

> "如果一个模型只允许一个人，一个相同的来源，一个相同人格调用呢？或许适用于仿生人领域，就像自己的大脑只能自己请求？"

- 定位：仿生人 / 具身智能
- 影响：多租户隔离问题从架构上彻底消失
- 深层含义：**连续性 = 身份**

### 演进 7：脑启发 + 计算机优势

用户的最终框架：

> "尽可能参考人脑的设计，同时兼顾计算机计算快的优越性。"

以及最后的问题：

> "有没有什么还可以加入的，模仿大脑设计的，但是充分发挥计算机的计算速度，也就是设计和速度相互弥补的东西？"

### 演进 8：语言策略 —— 先母语，后外语

用户提出：

> "人在长大的时候，是先学习母语，然后在某个时间将另一门语言作为外语，我们可不可以这样，只预留一种语言，另一种语言需要之后训练？"

> "前面说到先做英文吧？然后中文后面训练，你记录了吗"

- 母语选定 **英语**（通用、学习成本低、使用面广）
- 中文作为 **LoRA 适配器**，在英文阶段完成之后训练（详见 [15-language-plan.md](15-language-plan.md)）
- 其他语言：只保留基座的自然行为，"像不会英语的中国人面对英语一样"

**这条需求的本质：** 把"学习顺序"也纳入设计。模型像人一样先建立母语能力，再以低成本叠加第二语言——这也是"少数据、好效果"理念第一次落到具体机制上。

## 三、最终愿景

一个 **单用户、单人格、有持续记忆** 的模型：

- 运行在消费级硬件上（RTX 4060 Laptop 8GB 起步）
- 对话 / RP 质量体感接近闭源 flash 档模型
- 长上下文记忆一致性接近人
- 能一边对话一边行动（异步工具）
- 全部在模型内部，零外部系统
- 面向仿生人 / 具身智能

## 四、用户背景（用于判断建议层级）

- 用过 LM Studio、KoboldCpp，跑过 Qwen 等本地模型
- 了解 LoRA 与全量微调的区别（"LoRA 是外挂，全量微调是直接调整模型本身"）
- 在云端草草尝试过一次训练（用自己和朋友的聊天记录），**输出乱码**
  - 推测原因：chat template 不匹配（详见 10-risks.md）
- **没有现成训练数据**
- 数据理念：倾向"少而精"，关注"模型的学习质量"而非数据量
- 期望的工作方式：**自己出想法和决策，实现交给 AI**
- 时间投入：空闲时间做，不想花太多脑力

## 五、非目标（明确排除）

- 不做通用能力对标闭源前沿模型（做不到，见 07）
- 不做多用户服务
- 不做云端部署（当前阶段）
- 不追求手机端（当前阶段）
- 不发明全新架构（是"在已有工作上适配和改进"，不是从零预训练）
