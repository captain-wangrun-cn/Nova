# 14 · 硬件选型与显存带宽

> 回答"换带宽更大的显卡是否更好""双卡方案是否可行"。

---

## 一、解码速度的物理公式

```
解码速度 (tok/s) ~= 显存带宽 (GB/s) / 模型大小 (GB)
```

**推导：** 生成每个 token 都要把全部权重从显存读一遍。算力再强也要等数据。这就是 **memory-bandwidth-bound（带宽受限）**。

**结论：带宽是解码速度的第一决定因素。** 用户的直觉是正确的。

| GPU | 显存 | 带宽 | 生态 | 备注 |
|-----|:---:|:---:|:---:|------|

| RTX 4060 Ti 16GB | 16 GB | 288 GB/s | CUDA | 显存翻倍，带宽几乎不变 |
| RTX 3090 | 24 GB | 936 GB/s | CUDA | **二手性价比之王** |

| **AMD R9 Fury** | **4 GB** | **512 GB/s** | **无** | 2015 年，见下 |

### 本项目（约 5GB 模型）的解码速度估算

| 硬件 | 理论上限 | 说明 |
|------|:---:|------|
| RTX 4060 Laptop | ~51 tok/s | 基线 |
| RTX 3090 | ~187 tok/s | 3.7 倍 |
| R9 Fury | ~102 tok/s | **但装不下** |

## 三、AMD R9 Fury 评估（用户提出）

**规格：** AMD Radeon R9 Fury，2015 年，Fiji 核心，GCN 3 架构，4GB HBM1，512 GB/s，约 7.2 TFLOPS FP32，275W。

### 带宽确实高（是 4060 Laptop 的 2 倍）

用户观察正确：HBM1 让 Fiji 拥有 512 GB/s，超过 2023 年的笔记本 4060。

### 但四个致命问题

| 问题 | 说明 |
|------|------|
| **显存只有 4GB** | 装不下约 5GB 的模型 + KV Cache。带宽再高也没用 |
| **无 ROCm 支持** | ROCm 已放弃 GCN 3（Fiji）。没有官方计算栈 |
| **无现代矩阵单元** | 没有 FP16/BF16 快速计算，没有 INT8/INT4 硬件支持。量化推理会极慢 |
| **算力偏低** | 约 7.2 TFLOPS FP32，低于 4060 Laptop 的约 15 TFLOPS |

### 结论

**带宽思路正确，但这张卡不可用。** 它是"高带宽 + 低显存 + 无生态"的典型——2015 年 HBM 给了它带宽，但显存容量、算力和软件生态全部落后。

**教训：选卡要看四个维度——显存容量、带宽、算力、生态支持。缺一不可。**

## 四、双卡方案评估（用户提出："一张显存大，一张计算强"）

### 为什么双卡通常不能加速 LLM 解码

```
解码是严格串行的：每个 token 必须依次通过所有层

如果层被切分到两张卡：
   token -> GPU A 的层 -> 传输 -> GPU B 的层 -> 输出
                              ^
                        这里就是瓶颈

PCIe 4.0 x16 实际约 25 GB/s
显存带宽 256-1000+ GB/s
-> 跨卡传输比显存访问慢 10-40 倍
```

**结果：速度约等于较慢那张卡的速度，甚至更差。** 双卡不会给你 2 倍速度。

### 双卡真正的价值：容量，不是速度

```
2 x 12GB = 24GB  ->  可以跑 32B Q4 的模型
```

**双卡的意义是"能装下更大的模型"，不是"跑得更快"。**

### 但本架构有一个例外

**双通路架构天然可以分卡：**

```
GPU A: Chat 通路
GPU B: Agent 通路
         |
    只在交叉注意力点同步
         |
    预测编码门控使同步稀疏
         |
    通信量小 -> 分卡可行
```

因为两条通路**大部分时间独立计算**，只在少数交叉点同步。如果预测门控让同步很稀疏，跨卡通信开销可以接受。

**这是本架构的一个额外优势，但会增加实现复杂度。建议先单卡跑通，再考虑分卡。**

### 异构双卡（一张强算力 + 一张大显存）的问题

- 强算力卡会等大显存卡 -> 被拖慢
- 层分配很难均衡
- 驱动 / 框架支持复杂（CUDA 混合不同型号可以，但性能不确定）

**除非有明确需求（比如必须跑 32B），否则不推荐异构双卡。**

## 五、实际建议

| 场景 | 建议 |
|------|------|
| **现在（开发阶段）** | 用现有的 RTX 4060 Laptop，不买新卡 |
| 想提速 3-4 倍 | 二手 RTX 3090（24GB / 936 GB/s） |
| 想装更大模型 | RTX 4060 Ti 16GB 或 3090 |
| 预算充足 | RTX 5090 |
| 想要大内存 + 低功耗 | Apple Silicon（M4 Max 及以上） |

**重要：本项目当前阶段不需要换硬件。** 4060 Laptop 足够开发、训练 LoRA、验证架构。硬件升级应等到架构验证成功、确实需要更大模型或更快速度时再做。

## 六、带宽优化的软件手段（不换硬件）

见 [05-performance.md](05-performance.md)：

- 量化（减少要搬的数据量）
- KV Cache 量化
- MTP（一次搬运生成多个 token）
- 投机解码（一次验证多个 token）
- 预测编码门控（少算一条通路）

**在现有 4060 上，软件优化可带来 2-3 倍提升，效果接近换一张中端卡。**
