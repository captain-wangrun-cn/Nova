# 07 · 能力边界与诚实评估

> 本文记录对"能做到什么 / 做不到什么"的诚实判断。**不要美化**，这决定了项目的合理预期。

---

## 一、核心事实：两个不同的天花板

```
能力天花板（由参数量决定）      实际发挥水平（由训练 + 架构决定）
        |                              |
        v                              v
   4B 的天花板                     现在能达到多少
   远低于闭源大模型                大多数小模型只用了一半潜力
        |                              |
        +-------------+----------------+
                      v
        训练 + 架构创新只能抬高"实际发挥"
        永远无法突破"天花板"
```

**所有架构创新（双通路、预测编码、记忆压缩）都是在帮模型更接近 4B 自己的天花板，不是让它超过天花板。**

## 二、4B vs 闭源 flash 档模型

### 文本质量（分场景）

| 场景 | 4B（优化后）vs 闭源 flash | 说明 |
|------|:---:|------|
| 日常闲聊 | 85-95% | 差距很小，聊天不需要深度推理 |
| RP / 角色扮演 | 85-100% | 专精后可以持平甚至更好（风格 > 智力） |
| 创意写作 | 80-90% | 结构感稍弱，但可接受 |
| 指令遵循（简单） | 75-85% | 复杂格式容易出错 |
| 事实知识问答 | 50-65% | 差距明显，知识储备不够 |
| 多步推理 | 40-60% | 差距大，参数量硬伤 |
| 代码 / 数学 | 40-60% | 差距大 |

**结论：聚焦的对话 / RP 场景，4B 能做到 85%+。这是为什么本方向是对的——避开短板，发挥长板。**

### 上下文注意力

| 能力 | 4B（加记忆架构）vs 闭源 flash |
|------|:---:|
| 记住角色设定、人称、语气 | **90%+** （架构可弥补） |
| 检索几百轮前提到的细节 | **80-90%** （记忆压缩可弥补） |
| 长文一致性（不崩人设） | **80-90%** |
| 长上下文中的多步推理 | 40-55% （天花板限制） |
| 长上下文中的细微语义关联 | 50-65% （天花板限制） |
| 读到第 100 段突然理解第 3 段伏笔 | 45-60% （天花板限制） |

**关键：** 用户要的"注意力好"如果是**记住和检索**（RP 主要需求），架构能补到 80-90%。如果是**深度理解长文中的复杂逻辑**，那是参数量决定的，补不上。

## 三、4B vs 8B

| 能力 | 差距 | 能否靠学习弥补 |
|------|:---:|:---:|
| 常见知识（日常、常识） | 小（都懂） | — |
| 冷门知识（专业、罕见） | **大** | 部分 |
| 多步推理 | 中-大 | 不能（天花板） |
| 风格 / 流畅度 / 语气 | **几乎为零** | — |
| 指令遵循 | 小-中 | 可以学 |
| 长上下文一致性 | 小 | 架构可补 |

**通用能力差距 +10-15%，RP 场景仅差约 10%。** 用户担心的"知识差距巨大"在 RP 场景里是伪命题。

## 四、"像人一样后天学习"——能做到吗

### 关键事实：权重里加知识，极其困难

```
微调（Fine-tuning）擅长：改变行为、风格、格式
微调（Fine-tuning）不擅长：注入新的事实知识
```

为什么？微调是在**调整已有知识的表达方式**，不是在**新建知识存储**。喂它 100 条"某公司 2026 年营收 X"，它学会的是"这种句式下该输出什么"，而不是"记住了这个事实"。

**这就是为什么业界用 RAG（检索）而不是微调来加新知识。**

### 但人脑也不是靠"权重"学新知识的

人脑有两套记忆系统：海马体（快速、一次性、临时）+ 皮层（缓慢、需强化、永久）。**人学新东西先存海马体，再慢慢巩固进皮层。**

### 这正好对应本项目的记忆模块

```
人脑                    本架构
--------------------------------------
海马体（快速记忆）   ->   记忆模块（记忆令牌，即时写入）
       | 巩固                      | 巩固
皮层（慢速知识）     ->   权重（定期微调）
```

| 问题 | 答案 |
|------|------|
| 能像人一样后天学吗？ | 能 |
| 通过什么？ | **记忆模块**（即时学习）+ **巩固**（慢慢进权重） |
| 是后训练吗？ | **不是**。后训练是"一次性塑形"，不是"持续学习" |

### 训练阶段辨析

| 阶段 | 做什么 | 类比 |
|------|--------|------|
| 预训练 | 从海量文本学语言和知识 | 出生到成年，建立世界观 |
| 后训练（SFT/RLHF） | 塑形：听指令、说人话、有礼貌 | 上学，学规矩和礼仪 |
| 持续学习 | 不断吸收新知识 | 终身学习 |
| **巩固** | 把记忆慢慢沉淀成常识 | **睡眠** |

### 硬限制

```
可以学的：知识、风格、格式、特定技能、一致性
学不来的：推理的深度上限（由参数量决定）
```

4B 可以学会"知道很多事"，但学不会"8B 级别的复杂推理"。就像一个人可以背下整本百科全书，但不会因此变成数学天才。

## 五、诚实总评

| 期望 | 可行性 |
|------|:---:|
| 4B 在对话 / RP 场景体感接近闭源 flash | 可以 |
| 4B 长上下文记忆一致性接近闭源 | 架构可补 |
| 4B 通用能力接近闭源 flash | 不可能 |
| 4B 长上下文推理接近闭源 | 不可能 |
| **在特定场景做到体感越级** | **这才是真正的"不可思议"** |

**真正不可思议的不是"小模型打败大模型"，而是用一个 2.5GB 的模型，在特定场景里做到让人以为在用大模型。**

## 六、还有一个被低估的因素：训练数据

闭源模型强，不只是参数多：

- 训练数据量：闭源可能用了 10-30 万亿 token，本项目只能用几千到几百万条
- 数据质量：闭源有专门的数据团队清洗、标注
- 后训练：RLHF/RLVR 需要大量人类反馈和计算

**数据量上的差距，比参数量的差距还大。** 这也是"用很少的数据训练出好效果"天花板更低的原因——除非聚焦到极窄的场景。
