# 02 · 核心架构

> 本文描述模型的结构设计。所有维度参数应写成可配置，便于未来从 4B 升级到 8B。

---

## 一、基座选择

**Qwen/Qwen3-VL-4B-Instruct** —— 4B，多模态，Apache-2.0。详见 [13-decisions.md](13-decisions.md) D16。

| 属性 | 值 |
|------|-----|
| 参数量 | 4B |
| 精度 | BF16 |
| 模态 | Image-Text-to-Text |
| 架构 | qwen3_vl（Interleaved-MRoPE / DeepStack） |
| 许可 | Apache-2.0 |
| 生态 | 109 个量化 / 446 个微调 |

**视觉编码器不参与双通路复制**，作为共享组件。下文参数账本以 4B 量级为准。

### 英文作为"母语"

无论选哪个基座，英文仍作为基础能力语言（见 D02）。

### 参数账本（关键约束）

双通路会**复制中间层**，参数量接近翻倍：

| 配置 | 参数 | Q4 显存 | 4060 8GB |
|------|:---:|:---:|:---:|
| 4B 单通路 | ~4.0B | 2.5 GB | 舒适 |
| **4B 双通路** | **~7.9B** | **4.7 GB** | **舒适（推荐）** |
| 8B 单通路 | ~8.2B | 4.9 GB | 舒适 |
| 8B 轻分支（复制约 25% 层） | ~10B | 6.0 GB | 很紧 |
| 8B 双通路 | ~16B | 9.6 GB | 装不下 |

**结论：4B 双通路 ≈ 8B 单通路的计算成本，但多出一整套架构创新。这个交换是划算的。**

## 二、双通路结构

```
输入 tokens
    |
    v
+--------------------------------------+
|  共享层（前 6 层）                     |
|  共同理解输入，构建基础表征             |
|  不做交叉（类似早期感觉皮层共享）        |
+--------------------------------------+
    |
    +---------------+---------------+
    v                               v
+----------------+          +----------------+
|  Chat 通路      |          |  Agent 通路     |
|  层 7 - 30      |<-------->|  层 7 - 30      |
|  （对话/情感）   |  交叉     |  （行动/事实）   |
+----------------+          +----------------+
    |                               |
    +---------------+---------------+
                    v
+--------------------------------------+
|  共享输出层（后 6 层）                  |
|  学习门控融合：决定每条通路贡献多少       |
+--------------------------------------+
                    |
                    v
                输出 tokens
```

### 通路分工

| 通路 | 负责 | 记忆职责 |
|------|------|----------|
| Chat 通路 | 对话、情感、风格、语气 | 情感状态、关系、语气 |
| Agent 通路 | 工具、推理、世界状态 | 客观事实、服装、地点、时间线 |

## 三、交叉注意力：三种机制

| 机制 | 频率 | 粒度 | 人脑对应 |
|------|------|------|----------|
| **Gamma 级** | 每层 | 特征级绑定 | Gamma 振荡（30-100Hz）特征绑定 |
| **Theta 级** | 每 K 层 | 摘要级同步 | Theta 振荡（4-8Hz）记忆编码 |
| **全局工作空间** | 触发式 | 重要性广播 | Global Workspace 全局点火 |

**为什么不是每层都做全量交叉：** 参考人脑——大部分处理是局部的，只有重要信息才"点火"广播。

## 四、预测编码门控（核心效率机制）

参考 Friston 的 Free Energy Principle / 预测编码：

```
每条通路有一个小型预测器，估算另一条通路的当前状态
    |
    +-- 预测准确（偏差 < 阈值）--> 不通信，跳过交叉注意力
    +-- 预测偏差大            --> 触发交叉注意力，交换信息
```

**效果：** 闲聊时两条通路意见一致，几乎零通信开销；出现分歧或复杂情况时才深度交换。

**这也是最大的"免费提速"手段**：闲聊时 Agent 通路可低功耗待机，速度接近单通路。

## 五、与标准 MoE 的本质区别

| 维度 | 标准 MoE | 本架构 |
|------|----------|--------|
| 专家通信 | 路由器选一个，其余沉默 | 持续交叉注意力，实时交换 |
| 数据交换层面 | token 级路由 | **隐藏状态级（tensor 级）** |
| 协作方式 | 串行选择 | **并行处理 + 中间融合** |
| 分工粒度 | 每 token 独立选择 | 两条通路各自积累上下文理解 |

## 六、多语言策略

| 语言 | 实现 | 训练时机 | 说明 |
|------|------|:---:|------|
| 英语 | 母语（基座权重） | **阶段 0-1（先）** | 深度理解，所有基础能力用它训练 |
| 中文 | LoRA 适配器 | **阶段 2（后）** | 叠加在英语 RP 基础之上 |
| 其他语言 | 基座自然行为 | 阶段 3（按需） | 像"不会英语的中国人"一样面对 |

**顺序是硬约束：先把纯英文阶段做完，再叠加中文 LoRA。** 完整理由、要求、风险与未解决问题见 [15-language-plan.md](15-language-plan.md)（决策 D18）。

**要点：**
- 基座已"会"多语言，LoRA 教的是"怎么做 RP"，不是"怎么说中文"
- 各语言 LoRA 独立训练、独立升级、互不干扰
- 中文 LoRA 需含**中英混杂**样本（英文人名 / 地名 + 中文对话）
- 部署时可动态切换适配器

**为什么英语当母语：**

| 因素 | 英语 | 中文 |
|------|------|------|
| 预训练占比 | ~70-80% | ~10-15% |
| Token 效率 | 1x | ⚠️ 对 Llama 系是 ~2-3x，**对 Qwen 系差距远小于此，待实测**（见 15-language-plan.md 第 2.5 节） |
| 可用 RP 数据 | 大量 | 较少 |
| 模型内部推理 | 更强 | 稍弱 |

Token 效率对 8GB 显存尤其关键：同样内容，英文占的 KV Cache 更小，有效上下文更长、速度更快。

## 七、显存预算（4B 双通路，Q4）

| 组件 | 大小 |
|------|------|
| 共享嵌入 + 输出头 | ~0.3 GB |
| 双通路中间层（2 × 约 3.8B） | ~4.4 GB |
| 交叉注意力 + 门控（新参数） | ~50 MB |
| KV Cache（16K 上下文） | ~1.5 GB |
| **合计** | **~6.5 GB** |

留出约 1.5GB 余量给更长上下文与开销。

## 八、实现要点

1. 从 Qwen3-4B 复制权重初始化两条通路
2. 交叉注意力层、门控、预测器为**新增参数**，需训练
3. 所有维度（层数、隐藏维度、通路数）写成配置项
4. 单元测试必须覆盖：前向正确性、显存占用、交叉注意力的隔离性
