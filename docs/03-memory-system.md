# 03 · 记忆系统（核心创新）

> 这是整个项目**最重要的部分**。用户的核心诉求——"像人一样记住角色、故事发展、服装变化"——全靠这里实现。
>
> **硬约束：全部在模型内部。** 不是 RAG，不是外部数据库，不是外部代码。

---

## 一、需求原话

> "记住角色，以及自然的故事发展，某些重要因素（例如服装等）不会遗漏，比如前面换了一个服装后面就需要自然而然地记住并融入对话，总而言之就是和人一样。"

以及：

> "不是例如 toolcall 那种，是真正的以模型的方式储存在硬盘的可持续数据，就像大脑的长期记忆一样，他是以原始的形态，而不是转换成文字或者行为的，也就是以模型的方式，而不是 json 或者其他数据格式文件。"

## 二、技术命名

用户描述的东西在学术上有名字：**状态跟踪（State Tracking）** + **潜空间记忆（Latent Memory）**。

| 用户的描述 | 学术名称 | 代表工作 |
|------------|----------|----------|
| 模型自己生成的记忆向量 | Gist Tokens / Memory Tokens | Mu et al. 2023 |
| 压缩长上下文成向量 | Context Compression | AutoCompressor 2023 |
| 潜空间读写记忆 | Neural Turing Machine | DeepMind 2014 / 2016 |
| 记忆模块持续更新 | Neural Long-term Memory | Titans (Google) 2025 |
| 压缩记忆矩阵 | Compressive Memory | Infini-attention 2024 |
| 潜空间检索（非文本） | Latent Retrieval | RETRO (DeepMind) 2022 |

## 三、三层记忆架构

```
+----------------------------------------------------------+
| 第三层：权重记忆（长期）                                     |
|   · 语言能力、世界知识、人格                                 |
|   · 训练时固化，推理时不改变                                 |
|   · 类比：人的常识和性格                                    |
+----------------------------------------------------------+
| 第二层：压缩状态记忆（中期）  <-- 创新点                      |
|   · 固定大小的状态向量，持续更新                              |
|   · 旧对话压缩进这里，不占 KV Cache                          |
|   · 服装变化、剧情转折、承诺、伏笔 --> 存这里                  |
|   · 类比：海马体 + 工作记忆                                  |
+----------------------------------------------------------+
| 第一层：KV Cache（短期）                                     |
|   · 最近 N 轮完整细节                                       |
|   · 高保真，但会满                                          |
|   · 类比：还记得的刚才几句话                                 |
+----------------------------------------------------------+
```

## 四、人脑映射

```
人脑                          模型
---------------------------------------------------------
海马体（快速编码情景记忆）   ->  KV Cache（临时）
                                     |
睡眠时的记忆巩固             ->  会话结束时写入磁盘
（海马体 -> 皮层）                  （模型生成记忆令牌）
                                     |
皮层（分布式长期存储）       ->  .safetensors 记忆文件
                                     |
线索触发的联想回忆           ->  注意力自动匹配并读取
```

**人脑的两套记忆系统：**
- 海马体：快速、一次性编码、容量小、临时
- 皮层：缓慢、需反复强化、容量大、永久

**关键：人学新东西不是直接写进皮层，而是先存进海马体，再慢慢巩固。**

## 五、记忆令牌（Memory Tokens）

### 存储格式

```
nova_memory_<session>.safetensors
    ├── memory_tokens:  [128, 2560]   <- 128 个记忆令牌（模型原生维度）
    ├── memory_keys:    [128, 512]    <- 检索用的键（联想回忆的"线索"）
    └── _meta: {model_hash, version}  <- 仅用于安全校验，不是记忆内容
```

**记忆内容 100% 是模型原生张量。** `_meta` 只用于防止加载不兼容的旧记忆（表示漂移问题），它不是记忆本身。

### 写入流程

```
对话进行中...
    |
模型内部检测到"值得长期记住的东西"（换衣服、承诺、关键事件）
    |
模型生成一个记忆令牌 + 对应的键
    |
写入磁盘（.safetensors）
```

### 读取流程

```
新会话开始
    |
加载记忆文件 -> 记忆令牌拼接到上下文最前面
    |
对话中，当前上下文生成 query
    |
与记忆键做注意力匹配 -> 自动"想起"相关记忆
    |
自然融入生成
```

> ⚠️ **2026-09-22 实测更正（S4 / D31）："拼到上下文最前面"这一条在 L0 层被推翻。**
> 20 轮历史下把记忆插在最前面，寻址退化到 **1/3**，且生成质量崩（开始复读）。
> 原因是 RoPE 的长距离把 `Q·K` 抹平了。L0 的做法是**插在当前轮之前**（与问题的距离只有当前轮的长度），
> 实测 8/8。见 [reports/s4-memory-min.md](../reports/s4-memory-min.md) 第四节。

> 📄 **L0 落地实现（已核查，2026-09-22）：** [reports/s4-memory-min.md](../reports/s4-memory-min.md) —— 本节设计的
> `[128, 2560]` 记忆令牌 + `[128, 512]` 独立键是**要训练**的写入器 / 读取器，属**里程碑 2**；
> S4 先落地 [docs/09-speculative.md](09-speculative.md) 的 **L0「精确 KV」层**（记忆 = 区间内每个 cache 槽位的 K/V，
> 键 = 模型自己的 `Q·K`），**零新增参数、零训练**即达成"20 轮后取回"的验收标准（8/8）。

## 六、状态跟踪：以"换衣服"为例

```
故事开始: 角色穿红裙
    |
事件发生: "她换上了黑色礼服"
    |
状态更新: 服装 = 黑色礼服   <- 必须被持续维护
    |
20 轮后: "你今天真美" -> 模型自然知道指的是黑色礼服
```

### 双通路的分工（关键设计）

| 通路 | 记忆职责 |
|------|----------|
| Chat 通路 | 记住**情感状态、关系、语气**（她现在开心还是生气） |
| Agent 通路 | 记住**客观事实、世界状态**（服装、地点、物品、时间线） |

两个通路各自维护自己的记忆状态，通过交叉注意力同步。类比：情绪由杏仁核管，事实由海马体管，前额叶负责整合。

## 七、三个必须解决的问题

### 问题 1：表示漂移（最危险）

若之后微调了模型，旧记忆文件可能失效——因为模型的"语言"变了。

**解决方案：记忆模块与语言模型架构解耦。**

```
语言模型（可升级、换版本）
      <->  稳定接口
记忆模块（冻结，永不改变表示空间）
      <->
记忆文件（永久有效）
```

**这是架构上最重要的一个设计决策，必须在第一版就定下来。**

### 问题 2：寻址——怎么找到对的那条记忆

人脑靠联想（闻到味道想起某个人）。模型需要：
- 写入时计算一个"键"（key）
- 读取时用当前语境生成"查询"（query）
- 用注意力做相似度匹配

即 NTM 的核心机制，可训练。

### 问题 3：训练"什么时候写、什么时候读"（最难）

模型必须学会：
- 什么值得存（不是每句话都存）
- 什么时候该回忆（话题相关时才调）
- 怎么自然融入（不生硬地念出来）

**完全依赖训练数据**——需要大量"记忆写入 -> 多轮后回忆"的样本。现实中几乎没有，需要用大模型 API 合成。

## 八、遗忘机制（比记忆更重要）

人脑会遗忘。一个永远不忘的模型会：被无限增长的记忆淹没、变得迟钝、成为隐私噩梦。

```
近期记忆   -> 高保真、详细
中期记忆   -> 压缩成摘要
远期记忆   -> 只留"要旨"（gist）
不重要的事 -> 直接丢弃
```

可在模型"空闲"时（类比睡眠）做记忆巩固：压缩、合并、剪枝。

## 九、巩固机制（Consolidation）

```
1. 即时：新信息 -> 记忆令牌（几毫秒）
2. 短期：记忆令牌 -> KV Cache 复用（会话内）
3. 长期：空闲时，把重要记忆令牌蒸馏进权重（需少量微调）
4. 遗忘：不重要的记忆被剪枝
```

第 3 步就是用户所说的"像人一样后天慢慢学"，而第 1 步让模型**立即**能用上新知识。

## 十、与 DeepSeek KV Cache 的区别（重要）

| | KV Cache（DeepSeek 那个） | 记忆令牌（本项目） |
|--|--------------------------|-------------------|
| 本质 | 计算缓存 | 认知记忆 |
| 内容 | 精确的注意力键值（无损） | 压缩的表征（有损） |
| 生命周期 | 单次请求内，可跨请求复用前缀 | 跨会话持久 |
| 共享性 | 相同前缀可安全共享 | **绝对不能跨用户共享** |
| 大小 | 庞大 | 极小 |
| 出错后果 | 计算错误 | 隐私泄露 + 记忆串味 |

**结论：长期记忆用令牌（小），短期精确回忆用 KV（准），各取所需。**

## 十一、待验证构想

详见 [09-speculative.md](09-speculative.md)：

- **记忆精度分级**：L0 精确 KV / L1 高保真嵌入 / L2 压缩摘要 / L3 句柄
- **穷举式记忆检索**：精确最近邻搜索全库，超越人脑的"想起来 / 想不起来"
- **毫秒级实时权重更新**：Titans 式测试时训练
- **状态快照与反事实回溯**：精确回滚到某个时刻

## 十二、训练数据需求

需要合成的关键数据类型（现实中几乎没有）：

1. **状态跟踪样本**：先发生状态变化（换衣服），多轮后自然提及
2. **记忆写入样本**：什么该记、什么该丢
3. **记忆读取样本**：何时该回忆、如何自然融入
4. **遗忘样本**：什么该被淡忘
